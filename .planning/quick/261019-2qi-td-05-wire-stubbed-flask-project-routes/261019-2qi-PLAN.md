## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> Flask JSON routes | Request bodies and query strings are untrusted, and caller identity is a client-supplied userId (the existing project-wide model) |
| Flask -> MongoDB | Values placed in filters are interpreted by Mongo and can act as operators |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-q2qi-01 | Tampering / Elevation | all five routes, queryProject/getUser | mitigate | Reject non-str ids/names with 400 at the route; the DB helpers also return None/raise for non-str input; tests post {"$ne": ""} and snapshot collections |
| T-q2qi-02 | Information disclosure | /get_project_info | mitigate | assertProjectMember gate; same 403 for missing vs. non-member project |
| T-q2qi-03 | Information disclosure | /main, getUser | mitigate | getUser projects out the password field; tests assert "password" is absent from responses |
| T-q2qi-04 | Spoofing | userId-as-identity | accept | Same trust model as existing /api/hardware/* routes; adding a session system is out of scope per TD-05 constraints (Track A ACCT-04 owns sessions) |
| T-q2qi-05 | Tampering | /create_project duplicate race | accept | find-then-insert matches usersDB.addUser; PoC concurrency is low. No unique index is added in this plan |
